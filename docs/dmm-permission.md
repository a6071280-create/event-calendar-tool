> **現状（2026-08-13）: 収集は一時停止中。**
> 許諾は得られているが、DMM側のサーバーが自動アクセスを **HTTP 403** で遮断しているため

> User-Agent の偽装・アクセス元の変更などの回避策は**行わない**（アクセス制限の回避に当たるため）。

本ツールが DMMぱちタウンの店舗ページを自動取得する根拠の記録。
**この記録が本ツールにおける唯一の許諾根拠**であり、内容に変更・疑義が生じた場合は
`data/site-sources.json` の `dmm-ptown-*` を `enabled: false` にして収集を停止すること。

## この記録の限界（重要）

- 回答には**頻度・範囲・表記についての具体的な指定がなく**、付された条件は「著作権に準ずること」および
  「本件の利用は規約に抵触しない」という確認のみ。
  そのため本ツールは、**申請時にこちらから提示した条件を自主的な上限として厳守する**（下記の実装）。
- robots.txt の扱いについて明示的な言及がないため、**robots.txt の遵守は解除しない**。
  DMM の robots.txt が対象パスを禁止している場合、収集はコード側で自動的にスキップされる。
  その状態を解消したい場合は、robots.txt との関係について改めて DMM に確認を取ること
  （確認が取れるまで、robots.txt を無視する実装は入れない）。
- 担当者の交代や規約改定に備え、DMM からの回答原本（メール等）は店舗側で保管すること。

## 「著作権に準ずること」への実装上の対応

DMMぱちタウンのページから取得・保存するのは、**著作物性のない事実情報に限定**する。

| 保存するもの | 保存しないもの |
|---|---|
| 店舗名（自社マスタの店舗IDに紐付け） | ページ本文の抜粋・説明文（`detail` を保存しない） |
| 開催日 | 画像・レイアウト・その他の表現 |
| イベント名（識別に必要な最小限の名称） | 記事本文・レポート文章 |
| 出典名「DMMぱちタウン」と掲載元URL | |

実装: `data/site-sources.json` の各 `dmm-ptown-*` に `storeExcerpt: false` を設定し、
本文抜粋を DB に保存しない（`collector/src/adapters/sites.ts`）。
画面では出典名とともに掲載元ページへのリンク（「情報源を開く」）を常に表示する。

## 自主的に厳守する運用条件

1. 取得は **1日3回まで**（`.github/workflows/collect.yml` の cron: JST 6/12/18時）
2. 取得対象は **佐久市内6店舗の店舗ページのみ**（`data/site-sources.json` で管理）
3. User-Agent に連絡先URLを含めて明示（`saku-event-calendar-collector/1.0 (+リポジトリURL)`）
4. ホストごとに最低5秒のアクセス間隔（`collector/src/politeFetch.ts`）
5. robots.txt を毎回確認し、許可されないURLは取得しない
6. 社内利用のみ。取得データの再配布・転載・外部公開は行わない

## 実施状況

### 2026-08-13: 初回検証で HTTP 403（収集を一時停止）

許諾を受けて佐久市6店舗のページを収集対象に設定し、probe ワークフローで検証したところ、
**6ページすべてが HTTP 403** を返した（`docs/probe-report.md` 参照）。

| 事実 | 内容 |
|---|---|
| 応答 | 全6ページ HTTP 403 Forbidden |
| robots.txt | `https://p-town.dmm.com/robots.txt` 自体も HTTP 403 |
| アクセス元 | GitHub Actions（データセンターIP） |
| User-Agent | `saku-event-calendar-collector/1.0 (+リポジトリURL)` |

robots.txt の記述による拒否ではなく、**DMM側のボット対策（WAF等）が
データセンターIPまたは非ブラウザ User-Agent を遮断している**と考えられる。
運営事務所からの許諾は「規約上の許可」であり、**技術的なアクセス許可（ホワイトリスト登録）とは別**。

### 対応方針

- `data/site-sources.json` の `dmm-ptown-*` を `enabled: false` に変更し、収集を停止した。
  403 を返すエンドポイントへ1日18回アクセスし続けるのは適切でないため。
- **回避策は実装しない。** ブラウザを装う User-Agent への偽装、ヘッドレスブラウザによる回避、
  プロキシ経由でのアクセス元変更などは、いずれもアクセス制限の回避に当たるため行わない。
- DMMから技術的なアクセス許可（User-Agent または アクセス元IPレンジのホワイトリスト登録）、
  あるいはデータ提供の手段（API・データフィード等）の案内を得られた場合に限り、
  `enabled: true` へ戻して再検証する。
