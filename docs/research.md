## Step 2〜4: 情報源ごとの自動取得可否

| 情報源 | API | 自動取得 | 根拠 |
|---|---|---|---|
| P-WORLD | なし | **禁止** | [総合利用規約](https://www.p-world.co.jp/_info/user/rules1.htm)が「当社の許可なく本サービスを通じて配信されるデータ等を収集する行為、またはデータ等の収集が疑われるアクセス」を明示的に禁止。違反には法的措置の記載あり。 |
| DMMぱちタウン | なし | **禁止（要事前許可）** | [DMMぱちタウン利用規約](https://p-town.dmm.com/terms)および DMM 共通規約の禁止事項（自動的手段によるアクセス・情報収集）に該当。 |
| 店舗公式サイト | サイトによる | **条件付き可** | サイトごとに robots.txt / 利用規約を確認。許可される範囲で低頻度・UA明示のポーライトアクセスに限定。collector の robots.txt チェッカーが機械的に遵守を強制する。 |
| 公式SNS（X 等） | X API（有償） | **API経由のみ可** | X の画面スクレイピングは規約違反。API 契約をする場合のみアダプタを有効化する。 |
| その他情報サイト（みんパチ等） | なし | サイトごとに要確認 | 個別確認まで無効のまま。 |

### 結論（コンプライアンス方針）

1. **P-WORLD・DMMぱちタウンの自動スクレイピングは実装しない。** 両サイトは店長が目視確認し、アプリの「手動クイック登録」（情報源名・URL付き、数タップ）で取り込む。取り込み後の重複排除・履歴管理・差分検知はすべて自動。
2. **自動収集は許可された情報源のみ**。collector はアダプタ方式で、`data/sources.json` の `enabled` フラグと robots.txt チェックを通過した情報源だけを取得する。店舗公式サイトについて許可が確認できたものから順次有効化する。
3. DMM に対しデータ利用許諾（法人問い合わせ）を打診する価値はある。許諾が得られれば専用アダプタを追加するだけで自動化できる構造にしてある。

## アーキテクチャ決定

- **DB**: リポジトリ内 JSON（`data/db/`）。GitHub の履歴 + レコード内の変更履歴（`changes[]`）で「削除しない蓄積」を実現。サーバー不要。
- **自動更新**: GitHub Actions cron（1日3回, JST 6/12/18時）で collector を実行し、変更があればコミット → GitHub Pages が自動再デプロイ。
- **フロントエンド**: 既存の React + Vite アプリに「佐久市」タブ（日付×店舗マトリクス）を追加。`public/data/dataset.json` を読み込む。
- **差分検知**: AI 予測ではなく過去実績の機械的集計（`src/saku/lib/patterns.ts`）。閾値は `data/settings.json` で変更可能。

## 制約事項（サンドボックス）

本開発環境からは対象サイトへの直接アクセスがネットワークポリシーで遮断されているため、実データの自動取得検証は未実施。初期データは仕様の動作を実証するサンプルデータ（`demo` フラグ付き）で投入しており、実運用データは手動登録および許可済みアダプタ経由で置き換わる。
